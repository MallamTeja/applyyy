## Triggers on `applications`

BEFORE INSERT `guard_status_insert` → BEFORE UPDATE `guard_status_transition` (SECDEF),
`guard_tailored_profile_freeze`, `guard_failed_rerun`, `set_updated_at` → AFTER UPDATE
`log_status_change` (SECDEF, writes `application_events`). Together these make the status graph a
database-enforced state machine. No client can skip an edge, even one holding a valid JWT.

## Grants note

`anon` and `authenticated` keep Supabase's default full DML grants (TRUNCATE included) on 17
`public` tables. RLS blocks every row operation for `anon`. RLS does not cover TRUNCATE, but
PostgREST does not expose TRUNCATE, so the gap exists only for a direct SQL connection as those
roles. Rated low; tracked in the vulnerability doc.
