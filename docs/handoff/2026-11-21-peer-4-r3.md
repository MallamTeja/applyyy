## Engine rules (all in code, each with a named red-on-revert test)

1. **Core + JD fill:** core first (profile order), then JD-tiered master skills, then the model's picks, then master order. Up to `min(row.max, 7)` per group, at most 2 printed lines (`fillSkillLines`).
2. **Never-list:** blocked even if the JD names it or the model picked it; reported in `dropped`.
3. **Twins:** the profile's kept spelling wins (Unit Testing over Testing; LLM/SLM API Integration over LLM Applications), on top of the existing `skillTwinKey` dedupe.
4. **Aliases:** "data structures" credits DSA, "GCP" credits Google Cloud Platform, and so on.
5. **Most-needed first** (2026-11-18 21:47):
   - Inside a group: required > preferred > mentioned > core > picks > master order.
   - Across groups: tier-weighted JD coverage, then the model's group order, then profile order.
   - Projects and achievements: tier-weighted JD terms, a stable sort.
6. **Groups:** ≥ 5 (`SKILLS_MIN_GROUPS`), ≤ 6. The AI group is always seated, floor 5 (`min` on its row), refilled shortest-first if long names fall short.
7. **Master only:** a core name the master lacks matches nothing. Every seated ref is a master skill.
