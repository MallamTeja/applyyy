# Peer 2 bridge, round 6: one contact User-Agent on robots.txt and the page (edge), 2026-11-21

Written for the orchestrator (applyyy-68). Nothing staged, committed or deployed; no live access.

## Change

`supabase/functions/_shared/http/transport.ts`, inside the robots fetcher of `httpFetch`:
- master-robots builds the robots.txt request with `'user-agent': productToken` (the bare `applyy-scout`). The transport now replaces that same lowercase key with `cfg.userAgent`, so no second header is sent.
- `cfg.userAgent` is `DEFAULT_USER_AGENT` (`applyy-scout/1.0 (+https://github.com/MallamTeja/applyyy)`) unless a caller names itself. It is the same value the page request sends: one constant for both.
- Matching is unchanged: robots groups are still matched by `productToken`, which is derived from that same string. It is never browser-like (the 11-01 robots ruling).

**This file also carries the uncommitted r5 pacing change.** Gate r5 and r6 together, or commit r5 first.
