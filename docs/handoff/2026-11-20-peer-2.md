Owner: peer 2 (applyyy-4c). Orch: applyyy-dc. **Uncommitted; nothing deployed.** Web-only change (Vercel on push);
no edge function, no migration, no new op kind (so the aiEdit.ts strict-reader deploy order does not apply).

## Root cause (recon x3)

- `resume-assist` (server) checks no floors and no page fit. Both refusals come from the web.
- The web `planBatch` already judges the END state, but the two halves never shared a save:
  - the bullet `remove` auto-applied alone and hit the floor: "exp_aczen: 3 bullets, needs 4";
  - `new_bullet` is an attest (it writes the master first), so it always saved alone, fitted against the
    4-bullet resume: "Would run past one page".
- `swapPartners` paired only `remove_entry` + `add_entry` (projects).

## Fix (floors unchanged; only where they are checked moved)

1. `aiEdit.ts`
   - `swapPartners(ops, parents?)` also links a bullet `remove` with a `new_bullet` under the SAME entry.
   - New `bulletParents(structure)` maps a printed bullet ref to its entry ref.
   - `isPairedHalf` and `applyTogether` take `parents` and pass it on.
   - remove + `add_bullet` is deliberately NOT linked: both are pure and already auto-apply in one end-state batch.
2. `AiEditPanel.tsx`
   - Computes `parents` each render. Auto-apply, card pairing and Apply-all all use it.
   - A linked remove no longer auto-applies alone, and Apply all leaves it out (the `open` count now reads `allBatch`).
   - One click on either card runs the new `applySwap`, which sends `[remove, attest_bullet]` to `onEditBatch` as one save.
3. `ApprovalQueuePage.tsx`
   - `editRows` routes "exactly one `attest_bullet` + only bullet `remove`s" to `attestBulletRow(..., alsoRemove)`.
   - Any other mix with a master write is still refused whole.
   - `attestBulletRow` has a new required `alsoRemove` param; the plain attest passes `[]`.
4. `attestBullet.ts`
   - New optional `alsoRemove?: string[]`.
   - Before any read or write, the removals are proven on `current`, so a stale ref mints no master version.
   - After the proof, they are folded into `proven.resume`, so the single `fitEditToOnePage` and the single save see the end state.
5. `pageFitEdit.ts`: when a broken rule is a `N bullets, needs M` floor, the refusal appends:
   "To replace a line, ask for the removal and the new line in the same message; they are applied together."
