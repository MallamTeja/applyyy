# Peer 1 (b5), round 4: a thin job description counts as "No description" (2026-11-21)

Status: **DONE, uncommitted.** Nothing staged, committed, pushed, deployed or written live. All live reads were SELECTs.

## The rule (one place: `supabase/functions/_shared/screen/jd-substance.ts`)

A description is **thin** when it has fewer than **100 characters of role text**. Role text is what is left once the
description is split into lines and blank lines plus boilerplate lines are removed. The boilerplate lines come from a
closed list of 12 named patterns:
- **Generic:** equal_opportunity, eeo, affirmative_action, cookie, apply_now, not_the_right_fit, introduce_yourself,
  email_alerts.
- **Fractal's Workday tenant wrapper:** workday_fun_to_work, workday_passion_customer_focus, workday_wild_growth,
  workday_over_achievers.

A thin JD gets exactly the blank-JD treatment from fa315449. There is no new status and no new pill.

Callers:
- `screen-batch.ts:241` sets `blank = isThinDescription(description_raw)`. Today `blank` does one thing: it stops a
  `tech_gate_unclassified` drop.
- `apps/web/src/features/discovery/discoveredList.ts` sets `hasNoDescription = isThinDescription(description_preview)`.
  That function drives the "No description" pill. The web imports the helper by relative path, the same way it already
  imports `work-auth-gate.ts`.
