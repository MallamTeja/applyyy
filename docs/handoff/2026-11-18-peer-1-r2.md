## Toolbar restyle (Teja 21:58, queued task)

**Root cause:** the row used `.chip-btn`, defined ONLY in `features/settings/settings.css`. That stylesheet is imported only by the Answer Bank chunks (`AnswerBankPage.tsx:41`, `AddQuestionModal.tsx:14`). Routes are code-split, so on Discovered jobs the class matched nothing and each button fell back to its inline style or the browser default. Measured on prod:
- Buttons: `rgb(240,240,240)` fill in light, `rgb(107,107,107)` in dark. That is the UA default.
- Rules link: default blue `rgb(0,0,238)` (light) / `rgb(158,158,255)` (dark).
- Heights: 21 px vs 27 px.

It would also have looked different after visiting Answer Bank, because the CSS gets loaded then. The page's 4 other `chip-btn` uses (Clear results, the Undo in the reject strip, "show Ready", Load more) had the same bug.

**Fix:** reuse the global `.button` ladder from `styles/base.css` (always loaded). No new button system.
- Add a job by link: `button button--primary` (the one primary).
- Scout Watchlist, Remote Feeds: `button button--secondary`. Inline accent styles removed.
- Run pipeline: `button button--secondary discovery__toolbar-caution` (amber `--signal` edge; it spends Gemini on many rows).
- Rules (`<Link>`): `button button--ghost discovery__toolbar-link` (no underline).
- The 4 other page buttons: `button button--secondary button--small`.
- The only new CSS is the two `discovery__toolbar-*` rules in `DiscoveredJobsPage.css`. Tokens only, so no `[data-theme]`.

**After (measured):**
- All 5 controls are 31 px.
