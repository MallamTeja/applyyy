## P2 design (19:50, from the recon of the browser pipeline)

The browser pipeline that P2 moves server-side. File:line refer to `ApprovalQueuePage.tsx` (Page):
- **Row read** (user JWT + RLS):
  - `applications`: `tailored_profile, updated_at, tailor_refs, selected_jd_keywords, status`.
  - The pin is `tailored_profile.master_version`.
  - The pinned master comes from `master_profiles.profile` at that version, through `masterFromRow`.
  - `original = rebuildOriginal(tailor_refs, master, version)`.
  - `full = resolveFullMaster(master, version)`.
  - Guards: `current.master_version === original.master_version`, and original/full must not be null.
- **Pure batch:** `planBatch(current, pure, pureEdit, jd, master)` (Page:1977), then `saveTailoredEdit` with `expectedUpdatedAt` and the event (`EVENT_KIND`/`eventRef`, Page:223-298; `pureEdit` dispatcher, Page:433-488). Never with a repin.
- **attest_skill:** `attestSkill(...)` (Page:1666). It works at the pin, OR does a new master insert followed by a repin save.
  - Not atomic: the master can land while the row write fails (`masterInserted`).
- **attest_bullet:** `attestBullet(...)` (Page:1744), with the swap with N removes (Page:1953).
- **Ids:** `bN/eN/mN/nN` are minted in `buildAssistDraft` from the browser's diff and structure (aiEdit.ts:342-534). `resolveOne` (aiEdit.ts:714-833) maps ops to StoredOps, and `toEditAction` (:884) maps those to EditActions.

**Chosen shape (option a): the web sends its draft maps.**
- `server_apply: true`, `application_id`, `expected_updated_at`, and `refs`:
  - bN → ref
  - eN → {section, ref, bulletRefs}
  - mN → {ref, parentRef, section}
  - nN → {section, ref}
  - printed skills → {name, category, ref}
- The server never trusts these refs. Every action is re-checked against the row it reads, by the engine and by `tracesToMaster` at save.
- Option (b), the server rebuilding the diff itself, would mean porting diffAdapter + structureFromDiff + buildAssistDraft with identical numbering. Not chosen.

**Build order:**
1. `_shared/resume-edit/resolve-ops.ts`: a pure port of resolveOne/toEditAction over the maps, plus the S9j absolute-place ops.
2. `_shared/resume-edit/page-edit.ts`: `pureEdit`, `EVENT_KIND` and `eventRef`, ported from Page. They are twins until Page is granted.
3. attestSkill/attestBullet in `_shared`. BLOCKED on the tsconfig `paths` line: both import master-store, which types `SupabaseClient`.
4. `resume-assist/server-apply.ts`: read row → resolve → `planBatch` + save, with one retry on `changed_elsewhere` (S9d) → attests in order → per-op outcome list. It runs under `EdgeRuntime.waitUntil`, bounded by the wall clock, and records a refusal instead of running past it.
5. Write the chat exchange row server-side (ops + outcomes), so a closed tab still shows it.
6. Web: send the maps + `server_apply`; render the outcome list; no Apply buttons.
