## What changed

### Chat (`supabase/functions/resume-assist/assist.ts`)

1. **Per-group op cap.**
   - **Change:** every `add_skill` filed under one skill group now counts as ONE change against `MAX_OPS = 12`. Any other op counts alone. The helper is `capUnit` (group key, else the op's position).
   - **Top-up:** `topUpNamedSkills` uses the same counting, so it can still fill a group the answer already touches after 11 other changes.
   - **Why:** in keep7's 361 chat turns, 17 replies hit the cap on group fills ("add tools with 6, cs fund 5, backend 5, ai 5"), and Teja pasted the cap error back 3 times.
2. **`add_group {name, n}`. The MODEL writes it; the BROWSER never receives it.**
   - `parseAssistOps` expands it, before checks and the cap, into ordinary `add_skill` ops, using:
     - only that group's master skills that are not printed yet;
     - the job's missing keywords first, then master order;
     - at most `n`; a missing, fractional, non-positive or string `n` means the group size, `TOP_UP_GROUP_SIZE` = 7;
     - only while the group still fits one printed line (the web refuses a wrap). The owner saying "all" lifts both limits, as it already does for `add_skill`.
   - **Nothing to add:** an `add_group` for a group with no master skills left is refused: `"<group>" has no master skills left to add. Name the ones you want and they are added.` It is never filled with invented skills.
   - **Owner's count holds:** groups an `add_group` filled are skipped by the top-up, so "add tools with 3" stays 3.
   - **Schema and prompt:** the schema enum gains `add_group`, plus a new `n: INTEGER` field. The system text gets one `add_group` JSON line. The export `MODEL_ONLY_OP_KINDS = ["add_group"]` names the kinds the browser never receives.
   - **Why the web needs no change:** the web reader (`aiEdit.ts readAssistBody`) is untouched. It still receives only the 10 kinds it reads, so there is no reader-first deploy.
3. **Honest reply, the live stream.**
   - **Bug:** the NDJSON stream sent the RAW model note, so "I added Kafka" showed on screen until the result line replaced it.
   - **Fix:** the stream now runs `claimFreeSentences`, the same filter `honestNote` uses for the final note.
   - **No web change needed:** the server's note never contains a change claim at all, so the web refusing an op the server kept cannot make the note false either. The web's per-op cards and counts already state what landed.
4. **`set_role` example:** changed from `"Data Analyst Intern"` (the FamPay title) to `"Software Engineer Intern"`.

### Tailor prompt (`supabase/functions/_shared/tailor/prompt.ts`), the producer for e1f4b520's validator

With no terms found, the line reads `(none found; read the description)`.
- **New policy sections:**
  - **REQUIREMENT-TO-EVIDENCE** runs before any choice; a requirement with no evidence stays unaddressed.
  - **SUMMARY RULE:**
    - always return `summary`;
    - 2–3 sentences, about 45–60 words, written new for the job (the 33 ideals run 46–56 words);
    - names 2+ requirements and holds 1 real metric copied exactly from a cited item;
    - never a verbatim master summary or variant.
  - **BULLET RULE** replaces the word-list WORDING HINT:
    - each bullet is in the model's own words, with `sources`: its own ref first, plus siblings under the same parent;
    - every number and tech name must be in the sources, and every number of the ref bullet is kept;
    - no claim adjectives; about 20–30 words.
  - **ROLE TITLE RULE:** maps the job type to an allow-listed title, using the mapping from the 33 ideals (AI / Backend / Full Stack AI / else Software Engineer).
  - **WORKED EXAMPLE:** FICTIONAL, with `example_*` refs that exist in no master and no data from the owner's resume.
  - **SELF-CHECK:** 6 points, placed last.
- **Schema:**
  - Every bullet item in experience, projects, education, achievements and certifications now has a REQUIRED `sources: string[]`.
  - An experience item has an optional `role_title`, its enum built from `EXPERIENCE_TITLE_ALLOW_LIST` (imported from validator.ts as the single source).
  - The master renders `role_title options (put ONE in role_title): …` only under an allow-listed experience (`exp_aczen`).
- **Temperature:** `TAILOR_TEMPERATURE = 0.2` is exported. `tailor/index.ts` passes `generation: { temperature: TAILOR_TEMPERATURE }`. `client.ts` gets an optional `generation.temperature`; when it is absent the request body is byte-identical (the existing "without generation" test pins it).
