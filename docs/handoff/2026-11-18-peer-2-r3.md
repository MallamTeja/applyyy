### Where D6 differs from the brief

The brief asked for `.in(...)` on **this batch's keys**. That is not possible, because the twin key is `crossSourceKey()`, a fold computed in code. The `jobs` table has no column holding it. The narrowest filter the server can apply is the batch's board slugs. The old code already filtered on those slugs. The 2134 rows it found were simply too many for the 1000-row cap. Paging fixes this. Filtering on raw `title` would miss twins that differ only in letter case or punctuation, so I did not add it.
