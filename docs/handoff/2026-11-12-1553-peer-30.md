# 2026-11-12 15:53 IST: peer 1 (30) stops resume edits from wrapping a skill group

**Status:** done and gated. **Not committed.** This is a web-only change; Vercel ships it on push, and no function deploy or migration is needed.

## The rule (orch decision)
- An add that would wrap a skill group onto a second line is **refused**. The refusal names the full group.
- If the owner said **"all"** in the chat, the add goes through, and the save says the group now wraps.
- The line test is `skillGroupFitsOneLine` from `packages/resume-template`. That is the same helper the tailor, the trimmer and resume-assist use since 4b7e75a. The web imports it by relative path, as `renderPreview.ts` already does.

## Recon: where the adds go
- **There is no manual skill editor any more.** Commit 7211fd7c made the AI chat the only edit path. Every add lands in one of two places:
  - The chat `add_skill` op becomes `attest_skill`, which goes through `attestSkill` and then `addSkill`.
  - The page's own `add_skill` action goes through `pureEdit` and then `addSkill`.
- The only manual choice is the group picker on a chat card. Its group is checked too, because the check runs on the action that is actually saved.

## Files
1. **`apps/web/src/features/approval/tailoredEdits.ts`**
   - New `skillGroupWrapReason(resume, name, category)`: returns the refusal sentence, or null.
   - `addSkill` gains `wrap: 'refuse' | 'allow' = 'refuse'`. Refuse is the default, so it fails closed.
2. **`attestSkill.ts`**
   - The check runs **before any write**. A refusal after the master insert would have left a stray immutable master version.
   - `AttestArgs.wrap` is required. The test is `!== 'allow'`, so a missing value refuses.
   - An allowed wrap adds a line to `notice`. The page already shows `notice` as a `toast.info`.
3. **`aiEdit.ts`**
   - `SAYS_ALL = /\ball\b/i` is the same word the server's top-up reads.
   - It sets `allowWrap: true` on the stored `add_skill` card.
   - `readStoredOp` keeps the flag only when it is exactly `true`.
   - `toEditAction` passes `wrap: 'allow'`.
4. **`DiffView.tsx`:** `attest_skill` gains an optional `wrap?: 'allow'`.
5. **`ApprovalQueuePage.tsx`:** `attestRow` passes `wrap: action.wrap ?? 'refuse'`.
- **No new op kind, no new response shape, no migration.** A refused chat card shows its reason through the existing `ai-chat__error` line. There is no native dialog.
