### Flow and reuse (no new copies of a rule)

1. **Pick the row.**
   - Scan: `passed_filters`, oldest `updated_at` first, `description_preview` only (1000 rows).
   - `pickCandidate` keeps a row only if it is thin by `isThinDescription`, not in `skip_ids`, and not `manual`. Human-pasted rows are skipped, as matcher `skipGate` does.
   - The full `description_raw` is then read for the picked row, and thinness is re-checked on it.
2. **Liveness.**
   - Uses `postingCheckUrl` + `checkPosting` (`_shared/scout/queue-liveness.ts`) through scout-ats's robots-gated `fetchBoard`.
   - The board token comes from `company_watchlist` (provider + `company_slug`). Untracked means "unknown", which never closes a row.
   - Only an explicit "gone" closes. A soft page or 0 form fields never does.
3. **Read the page.**
   - Plain read first: `httpText` (robots on, strict default, `notFound: "null"`), then `pageText`.
   - The plain page must give ≥200 chars and not be thin. If not, one `renderPage` call (Vercel, the caller's JWT forwarded; the renderer accepts only `APP_USER_ID`, and the workflow signs in as that user).
   - **robots 429/5xx (`RobotsUnavailableError`)** → `retry_later`.
   - **robots disallow** → `still_thin`. NO render: the renderer has no robots check, so rendering would get around the rule.
   - **page 404/410** → `closed`.
   - **HTTP 429/5xx** → `retry_later`.
   - **bot wall or 403** → render.
4. **Closed** → `advance_application_status(→failed, 'matcher', {reason:'posting_closed', stage:'jd_refetch', evidence})`.
   - The RPC copies the reason into `failure_reason`.
   - The `passed_filters→failed` edge allows `matcher` (20260909234900:113). The only `failure_reason` constraint is "non-blank" (20261109211000).
   - **No migration needed.**
5. **JD found.**
   - Write `description_raw` and clear `tombstoned_at`, as `job-link-intake` `tagManual` does.
   - Then re-screen with **`preGateRow` from `matcher/tech-pregate.ts`** on the NEW text (tech, work-auth, experience_ceiling). It does its own `drop_reason` write and the stamp-guarded `→dropped_filter` move as `matcher`. **A drop stays a drop.**
   - A pass runs `runRowPipeline(PASSED_FILTERS_STEPS)` (matcher → tailor → auditor) in `EdgeRuntime.waitUntil`, which is job-link-intake's `startServerPipeline` pattern.
6. **Status moves:** only `advance_application_status`. The client is `createAuthorizedAppUserClient`, whose `createAppUserClient` carries the agent key header.

### One row per call

- **Why:** the background pipeline shares the isolate's 150 s wall clock with the read and the render (up to 60 s).
- **How the run moves on:** the workflow loops calls and sends the ids it already tried as `skip_ids`. The body is validated: an array of ≤200 uuids, otherwise 400.
- **Pacing:** 45 s after each `pipeline_started` (Gemini RPM).
- **When the run goes red:** a non-200 or a body of the wrong shape stops the run red; any row `error` turns the run red at the end.
