## What changed

**Contract (committed by you, `1efaa871`):**
- `TailoredBullet.sources?`
- `TailoredExperience.role_title?`
- Both are optional and copied AS HELD.

**`_shared/tailor/validator.ts`:**
- **AI-written bullets.** When `sources` is present, the bullet is judged by provenance instead of the word allow-list:
  - Every metric in the text must appear in the pooled sources (`invented_metric`).
  - Every tech name the text uses must be named by a source (`untraced_tech`). The vocabulary is the master's skills plus a fixed `PROVENANCE_TECH_TERMS` list, alias-aware (Postgres = PostgreSQL, k8s, JS/TS, node).
  - `sources` must be non-empty and include `ref` (`invalid_sources`).
  - Each source must resolve (`unresolved_ref`) and sit under the same parent (`misattributed_bullet`).
  - Entry-level `dropped_metric` (see the eval section above).
- **No `sources`:** the old path, byte for byte. Named test: "an old row with neither new field resolves byte-identical".
- **`EXPERIENCE_TITLE_ALLOW_LIST`** (exported; `exp_aczen` → Teja's 4 titles). An allow-listed `role_title` becomes `ResolvedExperience.role`. Anything else gives `disallowed_role_title`.
- **`empty_summary`:** a summary with refs but blank text. A null summary is still the content rules' question, so old null rows keep rebuilding.

**`_shared/tailor/content-rules.ts`:**
- `checkHeadline(headline, jobTitle)` plus `HEADLINE_FALLBACKS`.
- The headline must have the printable shape, name a role, and not be only an intern word.
- No seniority word is allowed at all. This is **stricter than the ruling's "never more senior than the JD's"**, on purpose: the candidate holds no seniority, and `cleanRoleTitle` already strips those words.
- Every word must be the job title's own (the plural "s" is folded), or the headline must be a fallback.
- With no job title, only a fallback passes.
- Every headline `cleanRoleTitle` produces passes this rule (named test).

**`auditor/master-facts.ts` (new) + the `auditor/index.ts` wiring:**
- **Step order:** a new step after the content-rules gate, before `auditApplication`. A hit goes `tailored -> failed` (the existing edge) with `stage: "auditor_master_facts"`.
- **What it compares:** identity, then every experience, project, education, award and certification display field against the pinned master. A role must be the master's or an allow-listed title. The headline must be the master's or a variant's own, or pass `checkHeadline` against `jobs.title`.
- **Why it is not in `checkContentRules`:** that function is also the web edit gate. Teja's dictated `set_role` (11-11) would be refused there. The auditor sees only fresh `tailored` rows, never a human edit.

**Not touched:**
- `validator-ats.ts`: nothing imports it, so it is dead code. It was not in scope; deleting it is your call.
- `_shared/audit/detector.ts`: not in my row. It still flags summary numbers, so the AI summary is non-blocking there.
