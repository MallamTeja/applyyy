## Cause

`canonicalSkillTerm` (`_shared/tailor/jd-keywords.ts`) matches a skill NAME against the vocabulary patterns.
- 11 terms use `exact()`, which is case-sensitive on purpose: Go, Spring, Express, REST, Spark, Helm, AWS, Azure, AI, LLM, RAG.
  The case rule exists so English words in posting PROSE ("go to market", "the rest of") are not counted as skills.
- A skill name is a whole name, never prose. So "azure" read as unknown, and the chat added both "azure" and
  "Microsoft Azure".

- One private `termForWholeName(name, patterns)`, with two pattern lists built once:
  - `CASE_BLIND_PATTERNS`: each pattern plus the `i` flag.
  - `CASE_KEPT_PATTERNS`: the patterns as written.
- `canonicalSkillTerm` (the export) uses CASE_BLIND and returns the canonical casing.
- `appearsInDecoded`, the prose matcher behind `keywordAppearsIn` and `extractJdKeywords`, uses CASE_KEPT. Its
  behaviour is therefore byte-identical, and the name fix cannot leak into posting matching.
- **Brief correction:** the brief asked for `"Microsoft azure" → "Microsoft Azure"`, but the vocabulary term is
  **"Azure"**. `canonicalSkillTerm("Microsoft Azure") === "Azure"` is already pinned (`jd-keywords.test.ts:229`), and
  every caller compares terms, not master spellings. So the new tests expect "Azure".
