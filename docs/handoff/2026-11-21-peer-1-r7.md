## What changed

**`supabase/functions/_shared/screen/screen-batch.ts`**
- **New planner type:** `PlannedInsertStatus = "passed_filters" | "dropped_filter"` and `PlannedApplicationInsert`.
  - `planScreenedApplications` (`ScreenedBatchPlan.inserts`) now returns `PlannedApplicationInsert[]`.
  - The type is closed, so a planner row at `discovered` cannot be written in code at all (§6).
- **Scout insert type:** `ScreenedInsertStatus` is now `PlannedInsertStatus | "discovered"`.
  - `ScreenedApplicationInsert` stays as the insert type for the scouts' unscreened fallback, used when the screen
    context fails to load: `scout-ats/index.ts:1082`, `worker/src/cli/scout.ts:472`, `worker/src/scout/remote-run.ts:562`.
  - All three are unchanged. A planned row is still assignable to the wider type.
- **Compile-time proof**, type-only with no runtime code: `type _PlannerCannotHoldDiscovered = Extends<"discovered", PlannedInsertStatus>` under
  `// @ts-expect-error`.
  - It sits in this file, not a test, because `supabase/functions/deno.json` excludes `*.test.ts` from `deno check`. A
    `@ts-expect-error` in a test file would never be checked.
  - CI's Deno check covers this file.
- **Comment fix:** the r3/W1 comment above the union is corrected. It said nothing produces `'discovered'`; in fact only
  the planner doesn't, and the scout fallbacks do. The stale `ScreenedInsertStatus (:44)` reference near
  `planScreenedApplications` now names `PlannedInsertStatus`.

**`supabase/functions/screener/queue.ts`**
- The `hold` case and the `QueueAction` union are deleted.
- `queueActionFor` is renamed to **`screenVerdictFor(insert: PlannedApplicationInsert): ScreenVerdict`**. With no hold,
  there is no "action" left to choose, only the verdict to write. Per the naming rule ("say what it is"), the old name
  would have described a choice that no longer exists.
- It is still exhaustive, with a `never` default.

**`supabase/functions/screener/index.ts`** (the hold site only)
- The import is renamed.
- `if (action.kind === "hold") continue;` is deleted.
- `action.verdict` becomes `verdict`. These are the two lines that used the deleted kind; nothing else in the file changed.

**Tests (`screener/queue.test.ts`)**
- The `discovered → hold` test is replaced by:
  - a pass/drop → verdict test;
  - a source-shape test: `const verdict = screenVerdictFor(insertResult);` flows straight into
    `persistScreenVerdict(db, app.id, verdict)`. It is a positive shape check.
- `git grep` shows no other caller of `queueActionFor` or `QueueAction` in the repo.
