## What changed

The self-match trap drove the design. `applicationHistory()` returns `awaiting_approval` rows too (`QUEUED_STATUSES`),
and the queue rows ARE those rows. Reusing the main run's key set as it stands would therefore match every keyed queue
row to itself and drop the whole queue. To prevent that:
- `auditorAppliedKeys(result, scope)` now takes a REQUIRED `AppliedKeyScope`: `"committed_and_queued"` for the main
  run (no behaviour change; its rows are `tailored`) or `"committed_only"` for the re-gate. `AppliedHistoryKeyRow`
  gains `committed` (the screener's `ApplicationHistoryRow.committed` already carries it).
- The already-applied check runs only on `awaiting_approval` rows. An approved row is itself committed and would
  match its own key.

### The migration

- It renames the guard. The name `guard_auditor_queue_drop_work_auth_only` would now be false. The migration drops
  the old trigger and function, then creates `guard_auditor_queue_drop_reason` with
  `coalesce(new.drop_reason,'') not in ('work_auth','already_applied')`. The same 42501 error is raised, and the
  same GUC `applyy.acting_agent` check applies.
- It updates the edge note.
- It is re-runnable: it uses `update` by key, `drop … if exists`, and `create or replace`.
- The header quotes the 11-11 rule. It explains why `already_applied` belongs to the same no-judgement class: it
  compares two rows' `(ats_provider, ats_job_id)` and reads no prose. It also explains why `experience_ceiling` stays
  out, and gives the deploy order.
- `drop_reason` is plain `text` (`20260909234700_core_tables.sql:377`): no enum or CHECK. The trigger was the only
  gate, so no other schema change is needed. `enum-parity` is untouched, because no status edge changed.

## SELECT preview of the 26 awaiting_approval rows (run read-only at 11:2x IST)

**Result: 0 of 26 would drop for already_applied, and 0 would be flagged for experience.** On today's data the first
run is a no-op on the queue.

The check was not vacuous:
- The committed key set holds 71 keyed rows, and it includes the Canonical greenhouse `5150422` original.
- The real parser (`requiredExperienceYears`, run over the 26 live JDs via a scratch script) read 25 JDs with no
  hard minimum and 1 at 0 years, against `max_years` 1. All 26 passed this same parser at screen time, so 0 was
  expected.
- Work_auth is not previewed, because its gate is TS logic. The existing regate already runs it every drain, so
  these 26 rows passed it.

```sql
-- Which awaiting_approval rows the new regate would DROP (already_applied) or REPORT (experience, stored years only;
-- JD-parsed years appear only in the run's experience_flagged list). Read-only.
with committed as (
  select lower(btrim(j.ats_provider::text)) as p, btrim(j.ats_job_id) as ats_id, a.id as app_id, a.status::text as status
  from public.applications a join public.jobs j on j.id = a.job_id
  where a.status::text in ('approved','applying','blocked_needs_human','needs_verification','applied','employer_screening','oa_pending','interview','offer','rejected','failed')
    and not (a.status::text = 'failed' and a.approved_at is null)
    and j.ats_job_id is not null and btrim(j.ats_job_id) <> ''
    and lower(btrim(j.ats_provider::text)) not in ('', 'other')
), ceiling as (
  select (config->>'max_years')::numeric as max_years from public.filter_rules where rule_type::text = 'experience_ceiling' and enabled
)
select q.id, j.company_name, j.title, j.ats_provider::text as provider, j.ats_job_id, j.min_experience_years,
  (select string_agg(c.app_id::text || ':' || c.status, ', ') from committed c
     where c.p = lower(btrim(j.ats_provider::text)) and c.ats_id = btrim(j.ats_job_id)) as committed_twins,
  case
    when 'manual' = any(j.discovered_via::text[]) then 'keep (pasted by Teja)'
    when exists (select 1 from committed c where c.p = lower(btrim(j.ats_provider::text)) and c.ats_id = btrim(j.ats_job_id)) then 'DROP already_applied'
    when j.min_experience_years > (select max_years from ceiling) then 'REPORT experience_ceiling (stored years)'
    else 'keep'
  end as verdict
from public.applications q join public.jobs j on j.id = q.job_id
where q.status::text = 'awaiting_approval'
order by verdict, j.company_name;
```
