### The orch's §6 conditions

1. `payloadFormat` defaults to `"json"`. Proven by "an adapter that declares no payloadFormat is fetched as json"
   (functions), "condition 1: … still sends Accept: application/json" and "condition 1: a non-JSON body for a JSON
   adapter is an error, never empty text" (worker).
2. A detail page without a usable JobPosting is a counted skip. That covers no JSON-LD, malformed JSON-LD, a
   non-JobPosting, no or blank title, no location, and a foreign or missing url. Proven by "a detail page without a
   usable JobPosting is a counted skip, never a blank job" (8 cases). A sitemap that isn't a sitemap stalls the cursor,
   so the loop FAILS the board rather than reading it as empty.
3. There is no bypass path. The adapter makes no request itself. Every page, sitemap and detail alike, goes through
   `collectBoardPages` → the scout's transport → `gateRobots` (worker) or `httpFetch` robots (edge). Proven by the two
   worker "condition 3" tests and the edge disallow test.

### Adapter details worth knowing

- **Listing = sitemap.xml.** Atlassian's HTML listing (`/jobs/search?ss=1&in_iframe=1`) is a 164-byte JS redirect to
  atlassian.com. The sitemap is published in each tenant's robots.txt (`Sitemap:` line).
- **Detail by id only.** `/jobs/27181/job?in_iframe=1` serves the same page as the slugged URL (probed live). Every
  tenant's robots.txt disallows `/jobs/*login` and `/jobs/*candidate`, which would also match a slug containing those
  words, so using the id keeps slugs out of the path.
- **Location.** iCIMS writes the literal `"UNAVAILABLE"`, which is dropped. ISO country codes are spelled out via
  `Intl.DisplayNames`: `IN` → `India`, because the work-auth gate deliberately leaves bare `IN` unread (it could be
  Indiana). Numeric region codes (Singapore `01`) are dropped. Several places are joined with `;`, the gate's part
  separator. TELECOMMUTE with no address → `Remote`.
- **Date.** JSON-LD `datePosted` → `{ source: "remote_feed", published }`, which is the strict ISO-shape reader.
  ⚠ Naming debt: the variant is called `remote_feed`, but iCIMS isn't a remote feed. A dedicated `"icims"` variant
  needs a `_shared/normalize/posted-at.ts` change outside this parcel. Small follow-up.
- **Identity guard:** declared null (the sitemap names no company), like lever and ashby. The tenant subdomain in the
  token already names the company.
- **Cost (ponytail ceiling):** one detail GET per job per poll, with no "already stored" skip. Atlassian took 36 s at
  1 s pacing. The cap is 60 pages; a bigger board fails visibly. Skip stored ids before the detail read if tenants grow.
- **Edge pacing:** scout-ats's `httpFetch` has no pacer, so the edge scan reads an iCIMS board unpaced (Workday is the
  same there today).
