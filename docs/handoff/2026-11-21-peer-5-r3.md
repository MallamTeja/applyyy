The strict reader works in three steps: shape, then calendar, then parse (§6).
- **Accepted:**
  - `YYYY-MM-DD`, read as midnight UTC.
  - `YYYY-MM-DDTHH:MM:SS`, with an optional fraction and an optional `Z`/`±HH:MM`. A datetime with no zone is read as UTC, never as the runner's local time.
- **Refused, giving a null source date, so the caller falls back to `first_seen_at` labelled `derived`, or `unknown` on a first poll; never "now", never `exact`:**
  - non-strings
  - "-5" and "5" (the V8 traps)
  - impossible calendars such as `2026-02-30` and `2026-13-01`, caught by a UTC round-trip
  - hour 25
  - a space separator
  - US order
  - `T09:30` with no seconds
  - empty strings and prose
  - dates before 2000 (reuses `EARLIEST_REMOTE_POSTING`)
- Age is never a drop. The date feeds display and sort only (Teja's ruling). Nothing in this change reads age.
