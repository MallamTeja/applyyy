## `?mode=liveness`: DONE in code, NOT deployed

- No param: the full scan, unchanged (the web Scan button).
- `liveness`: the sweep.
- Anything else: **400 `unknown_mode`, before auth**.

The sweep runs after the kill switch and before the watchlist poll, the screener and the board loop. For each enabled watchlist board that holds an `awaiting_approval`/`approved` row, it does four things:
1. Reads the listing, read-only.
2. Applies the scan's identity and emptied-board refusal.
3. Runs `planDisappearances` as a **verdict only**.
4. Confirms absent queue rows on their posting endpoint.

That keeps both proofs. The orch approved this deviation from "zero board polls" at ~23:10. Then it runs the feed liveness pass.

It does NOT do any of these: upsert jobs or applications, screen, read Workday detail, write watchlist telemetry, or write planner marks. The queue read uses `count: "exact"` and **refuses with a 500 on truncation**.

To share code without duplicating it, I moved the scan's own blocks into helpers above the handler. Behaviour is unchanged:
